# 功能与平台差异

2026-10-24：Maven 与 iOS Git Pod 的默认版本统一为 `1.0.0` 未发布候选，基于远端 main `4ebb1c91c62cede98a49e78ecb8e870bc3cdf860`，未改公开 API、SDK 配置或宿主接线。Jenkins 构建、回归与精确发布消费尚待本轮实跑；下述 2026-10-18 / rc 版本记录保留历史边界，不代算 1.0.0 或设备验收。

核查日期：2026-10-18。源码基线：`0a63861` 加本轮发布候选改动，Maven 候选版本 `0.1.0-rc.3`、iOS Git Pod `0.1.0-rc.1`。首版提供 Maven 与 Git Pod 两个渠道，
远程消费由具体宿主验收；不包含动态 SDK 或真实热更新验收。

## 模块与公开能力

| 层 | 包/公开入口 | 当前职责 |
| --- | --- | --- |
| core | `io.github.gycrosskit.dynamicpage`，`DynamicPageRequest`、`DynamicPageConfiguration.open/prepare`、`DynamicPageRuntime`、`DynamicPageLoader`、`PreparedDynamicPage` | 请求契约与显式 runtime 分发 |
| core 网络 | `DynamicNetworkRequest`、`DynamicNetworkResponse`、`DynamicNetworkTransport` | JSON 网络模型和宿主 suspend gateway |
| core 能力 | `DynamicCapabilityRequest`、`DynamicCapabilityResponse`（网络回执别名）、`DynamicCapabilityTransport` | JSON capability/operation/paramsJson 和宿主 suspend gateway |
| Kuikly | `io.github.gycrosskit.dynamicpage.kuikly.DynamicNetworkModule` | callback request/invoke/invokeTask/cancel/dispose |
| native KMP | `DynamicNetworkHandler`、Android 注册扩展、OHOS 注册函数 | 每 Renderer 独占请求 owner |
| iOS Swift | `GycDynamicNetworkModule`、`GycDynamicNetworkHandler` | 原生 Module 与宿主已有 Shared 闭包接线 |

没有独立 CMP UI、实际页面下载器、注册表、缓存、路由替换或 SDK adapter。loader 只是宿主导航的装载契约。

## 功能合同

| 能力 | 默认值与边界 | Android/iOS/OHOS |
| --- | --- | --- |
| 页面开关 | provider 默认 none；none、无 runtime、provider 不匹配为 UNAVAILABLE | 共用 core 实现，宿主需显式提供 runtime |
| 页面请求 | module/page 为 1..128 字符标识，首字符英文或下划线，其余英文、数字、下划线、点、短横线；paramsJson 必须为 <=64 KiB UTF-8，按 kotlinx.serialization 解析为 JsonObject（不承诺 RFC 严格解析） | 相同验证；无真实动态页展示 |
| runtime 结果 | OPENED/UNAVAILABLE/INVALID_REQUEST；取消继续抛出，普通异常归为 UNAVAILABLE | 不把 OPENED 扩展为下载/热更新证明 |
| 页面准备 | prepare 可挂起且不得挂载；none/空值/缺 loader/不匹配/非法输入返回 null，取消抛出，普通异常返回 null；最终 open 同步挂载，OPENED 交页面持有，否则 close | 宿主导航复核准入与 owner，不新增第二套页面/路由；adapter 负责交出前的资源清理 |
| 网络输入 | method 仅 GET/POST，另有 path/query/bodyJson；不接受 header、Token 或 SDK 凭据；协议 JSON <=512 KiB | 路由及业务权限由宿主 transport 负责 |
| 通用能力输入 | capability/operation 首字符英文或下划线，其余英文、数字、下划线、点、短横线，长 1..128；paramsJson 必须为 JsonObject；含 envelope 总量 <=512 KiB；拒绝混合网络/能力请求 | 默认能力 transport 返回 unavailable；业务授权和具体能力归宿主 |
| 网络/能力输出 | status 仅 ok/unavailable/invalid_request/forbidden/failed；可选 httpStatus/bodyJson；输出 <=512 KiB | handler 捕获的异常映射 failed，不回传异常/请求原文；宿主返回的失败 bodyJson 由宿主契约解释 |
| 短调用并发/超时 | request/invoke 在发送端与 native handler 各共用最多 8 请求；重复 requestId 拒绝；native 30 秒，页面桥兜底 31 秒 | 取消和 dispose 清 pending，终止后不交付旧业务结果；原生回执仍终结一次；关闭后新调用返回 unavailable |
| 长任务 | invokeTask 使用 wire method task 和原 capabilityRequest；独立最多 16 在途，不占短请求槽位，不套 30/31 秒超时；相同 512 KiB 边界与输入验证 | 配置、会话、Auth、音效和页面事件各自等待；只交付一次最终回执，复用 cancel/dispose 与相同 native handler；业务或原生能力负责 deadline，调用方负责页面生命周期取消 |
| 生命周期 | Module/handler 每 Renderer 独占；不关闭进程级 HttpClient | 原生 Receiver 分别处理平台线程与销毁门禁 |

能力 Module 的历史名字与回执类型不改：旧 request/cancel wire 不新增 capabilityRequest=null，
避免已发布旧接收端因未知字段拒绝；invoke/task 才发送 capabilityRequest。Android/OHOS 保留单 factory 注册入口，
新增双 factory 重载；同一个 Renderer 仍只有一个 handler。iOS 配套 Pod 通过已有 call 闭包转发任意 method，
本轮 Maven 候选为 rc.3；Swift 源码和转发契约未变，Git Pod 保持 rc.1。旧 Maven rc.2 不含 invoke/invokeTask 源码 API。

长交互必须使用独立 task 槽位，不能仅为适配选图、认证或客服而放宽全部短请求超时。
调用方须在页面离开、事件收集停止或销毁时取消 task，并在页面最终销毁时 dispose；宿主操作继续遵循已有业务或 SDK deadline。
若能力提供一次 wait 下一事件，上层可以按页面生命周期循环 invokeTask；组件不维护业务订阅、事件队列或全局重试。
task 不传 native 对象、不增加多回调，不要求修改 OHOS C callback context 的持有协议。

同一页面的随包版本与未来在线更新版本共用同一通道。宿主 Koin 负责 native 能力装配，动态业务包自己构造 Repo/ViewModel
及其业务依赖；不跨通道传递 Koin、Repo 或 native 对象。旧网络 request 保留兼容；宿主可通过
invoke(http.execute) / task(http.read/release) 提供通用 HTTP，业务包沿既有 Repository 解析。
组件不接管 typed API/ApiResult，也不提供 Shiply adapter 或动态包执行。

## 平台接收端差异

| 平台 | 实现与 SDK | 待验证边界 |
| --- | --- | --- |
| Android | Kuikly 2.29.1 `KuiklyRenderBaseModule`；Main 接收，onDestroy 关闭 owner | Renderer 重建、迟到 callback 和设备网络 |
| iOS | OpenKuiklyIOSRender 2.29.1 `KRBaseModule`；Main handler，SDK 负责 Context callback 排队；invalidate 同锁关闭 | 本轮已通过 iOS Simulator 宿主 Native 链接；未执行完整 Xcode App、真实 SDK queue 或设备销毁验收。Git Pod 安装及原生 receiver typecheck 见历史记录 |
| OHOS | 2.29.1 HAR 官方 header 子集 cinterop；K/N `KRRenderModuleRegisterV2`、StableRef owner、递归 mutex 保护 callback/析构 | 本轮已通过宿主 .so 链接；完整 HAP 装载、主线程调度和真机 destroy-before-response 须由宿主独立验收。同版 C 导出核验见历史记录 |
| CMP/JS | 未实现独立 UI；未配置 JS target | 不属于本轮验收 |

OHOS ABI 来源为本机 OHPM cache 中 `@kuikly-open/render@2.29.1` HAR，按宿主 lockfile
integrity 读取，同版原型已核对。context 是 SDK 管理的 opaque handle，组件不解引用或自行 free；
页面取消/dispose 会结算原请求及控制调用的非空回执，避免长驻 Renderer 积累 context；业务 callback 已在发送端撤销。
Renderer 原生析构后保留 closed 门禁，不再调用可能失效的 SDK context；完整销毁行为仍需真机验收。
参数在 C 调用内复制，onDestruct 关闭 owner 并立即释放 StableRef，mutex 随仍在途 owner 的 GC cleaner 释放。
组件不重复实现 ArkTS HTTP、业务 NAPI 或第二份 Ktor runtime。

Kuikly 2.29.1 `clearTimeout` 与 `Module.removeCallback` 都只删除 GlobalFunction；没有公开的
native timer cancel API。本组件通过本页面 pagerId 删除回调及其闭包，底层延时 event 可能在原到期时间
触发为空操作；不声称取消了 Renderer 原生定时器。
